# نظام الشيباني المحاسبي والإداري المتكامل — الإصدار 2.2.3 (Supabase + Interactive Mode)

تمت إعادة هندسة وتصميم **نظام الشيباني المحاسبي** بالكامل ليكون واجهة ERP محاسبية ومخزنية تدعم العمليات الأساسية، مع واجهات عصرية مستوحاة من الهوية البصرية لمحلات الشيباني (الأخضر الزمردي الملكي `#0D4436` والذهبي التراثي `#C89B3C`) ودعم كامل للوضعين النهاري والليلي (`Light / Dark Mode`).

## أبرز وظائف وميزات النظام

1. **إعادة تصميم شاملة لجميع نوافذ النظام (14 نافذة رئيسية ومنبثقة)**:
   - **بوابة الدخول التفاعلية**: تصميم مزدوج يعرض هوية محلات الشيباني مع إمكانية الدخول المباشر إلى **وضع المحاكاة التفاعلي الفوري** بـ 3 أدوار (`مدير النظام`، `محاسب`، `كاشير`) أو تسجيل الدخول لقاعدة بيانات Supabase الحية.
   - **لوحة التحكم التنفيذية**: بطاقات مؤشرات أداء (KPIs) بأيقونات واضحة، مخطط أعمدة بياني لمقارنة المبيعات والمشتريات والمصروفات، أرصدة الصناديق الحية، وتنبيهات إعادة الطلب.
   - **نقطة البيع التفاعلية السريعة (POS)**: شاشة كاشير متكاملة مقسمة إلى كتالوج أصناف مرئي مع فلاتر تصنيفات وبحث فوري، وسلة بيع حية مع أزرار زيادة/إنقاص الكمية، اختيار الوحدة، وترحيل وطباعة فورية.
   - **نافذة الفواتير الموحدة (مبيعات، مشتريات، مرتجعات)**: جدول بنود تفاعلي شبيه بـ Excel مع إمكانية تعديل الوحدة والكمية والسعر، وإضافة وحدات جديدة للصنف من نفس النافذة، وحفظ سعر الشراء الداخلي المحمي للمدير والمحاسب.

2. **معالجات برمجية مهمة في الواجهة**:
   - **إصلاح خطأ فشل الفواتير بالعملات الأجنبية (SAR/USD)**: كان الكود السابق يعطل حقل العملة (`currencySelect.disabled = true`) عند إضافة أول صنف، مما يؤدي لحذفه من `FormData` وإرسال العملة `undefined`. تم إصلاحه بحفظ العملة في متغير الحالة `activeSaleCurrency`.
   - **إصلاح عرض المستندات (`viewDocument`)**: أصبحت نافذة المعاينة تتعرف ديناميكياً على الأنواع الـ 7 (`فاتورة مبيعات`، `فاتورة مشتريات`، `مرتجع مبيعات`، `مرتجع مشتريات`، `سند مصروف`، `سند قبض`، `سند صرف`) مع دعم الطباعة الرسمية A4 والطباعة الحرارية 80mm.
   - **إصلاح تعديل الأصناف والأطراف بعد وجود حركات**: قفل الحقول المحمية برمجياً في الواجهة (`الوحدة الأساسية`، `متوسط التكلفة`، `الرصيد الافتتاحي`) عند وجود حركات مرحّلة لمنع أخطاء Triggers قاعدة البيانات.
   - **الحفاظ على أسعار الوحدات الفرعية المخصصة**: استبدال حقل النص البسيط بجدول وحدات متعدد داخل نافذة الصنف وتحديث دالة `save_product`.

3. **وظائف محاسبية ومخزنية متاحة وفق إعداد قاعدة البيانات**:
   - **مرتجعات المبيعات ومرتجعات المشتريات (`sale_return` & `purchase_return`)**.
   - **كارت حركة الصنف (`Item Stock Card`) وتسوية الجرد المخزني (`post_stock_adjustment`)**.
   - **كشف حساب تفصيلي للعميل والمورد (`Party Statement`) مع عمود الرصيد الحي (`v_party_balances`)**.
   - **التحويل بين الصناديق ومصارفة العملات (`post_cash_transfer`)**.
   - **إثبات القيود اليومية اليدوية المتوازنة (`post_manual_journal_entry`) ودفتر الأستاذ العام لكل حساب**.
   - **قائمة المركز المالي / الميزانية العمومية (`Balance Sheet`) وتصدير التقارير بصيغة CSV**.

## ترقية قاعدة بيانات Supabase

**لا تشغّل ملفات الترقية على قاعدة الإنتاج قبل أخذ نسخة احتياطية ومراجعة حالة الملفات التي سبق تنفيذها.** ملفات `01` إلى `05` تعتمد على الجداول والدوال الأساسية الموجودة في مخطط `shaibani_erp`، ويجب تنفيذ الترقيات غير المنفذة بالترتيب الرقمي. بعد اكتمال `05`، نفّذ الملف التالي إلزامياً لتقوية صلاحيات الوظائف المحاسبية والتحقق من مدخلاتها:

- `supabase/patches/06_security_and_validation_hardening.sql`
- ثم `supabase/patches/07_product_duplicate_guard.sql` بعد مراجعة تقرير التكرارات.
- لإضافة حذف الأصناف والعملاء غير المرتبطين وإلغاء الفواتير بأثر عكسي آمن، نفّذ `supabase/patches/08_safe_record_deletion_and_invoice_voiding.sql` بعد النسخ الاحتياطي، ثم شغّل `supabase/verification/deletion_feature_check.sql`.
- أبقِ المخطط الداخلي `shaibani_internal` خارج قائمة **Exposed schemas** في إعدادات Data API؛ التطبيق يستخدم واجهات RPC الموجودة في `shaibani_erp` فقط.
- ثم شغّل `supabase/verification/security_hardening_check.sql`؛ المطلوب أن تكون `anon_can_execute = false` و`authenticated_can_execute = true` لكل وظيفة حساسة.

لا تشغّل الملف المرجعي `supabase/reference_only_do_not_run/202610310001_initial_erp.sql.txt` على قاعدة المشروع الحالية.

## الاعتماديات الخارجية

- Supabase JavaScript: الإصدار المثبّت `2.118.0` عبر `esm.sh`.
- SheetJS: تم تحديث محمّل Excel إلى الإصدار الرسمي `0.20.3` عبر CDN الرسمي، ولا يُحمّل إلا عند استيراد ملف Excel. يتطلب استيراد XLS/XLSX اتصالاً بالإنترنت عند أول تحميل للمكتبة.
- الواجهة ثابتة ولا تحتاج إلى خطوة بناء؛ يمكن تشغيل الفحص المحلي عبر `npm run check` (أو `node scripts/validate-project.mjs`).
- اجتياز الفحص المحلي لا يعني اعتماد النظام للإنتاج؛ يجب تطبيق الترحيلات والتحقق منها على قاعدة اختبار وإجراء اختبارات قبول فعلية.

## العمل دون اتصال والمزامنة — الإصدار 2.2.2

أضيفت طبقة Offline-first لدليل الأصناف ووحداتها وكميات المخزون باستخدام `IndexedDB`، مع طابور عمليات محلي يعاد إرساله إلى Supabase عند عودة الاتصال. بعد تسجيل الدخول أثناء الاتصال وتحميل شاشة الأصناف مرة واحدة، يمكن للجهاز المصرح له عرض الأصناف والبحث عنها وإضافتها وتعديلها وتحديث كمياتها دون اتصال، ضمن حدود الجلسة المحلية الصالحة.

تظهر اقتراحات الأصناف أثناء الكتابة في حقول الصنف، ويُفحص الاسم ورمز SKU بعد توحيد أشكال الحروف العربية والمسافات لمنع التكرار محلياً. أضيف ترحيل SQL رقم `07_product_duplicate_guard.sql` لتطبيق المنع على مستوى قاعدة البيانات أيضاً بعد فحص التكرارات القائمة ومعالجتها.

**تنبيه:** لا يدعم هذا الإصدار ترحيل الفواتير والمرتجعات والقيود والسندات والتحويلات والمصروفات دون اتصال. تُحجب هذه العمليات أثناء العمل دون إنترنت لتجنب مستندات مالية غير متزامنة أو مكررة. راجع `README_OFFLINE_FIRST_AR.md` لمعرفة خطوات التفعيل وحدود الوظائف وتعارضات المخزون.

وضع المحاكاة التفاعلي يبقى بيئة تجريبية منفصلة تعتمد بيانات محلية في `localStorage`، ولا يمثل جلسة Supabase حية أو بديلاً عن المزامنة الفعلية.

## حذف الأصناف والعملاء وإلغاء الفواتير — الإصدار 2.2.2

- أضيف إجراء حذف نهائي للأصناف والعملاء غير المرتبطين، بصلاحية مدير النظام فقط.
- يُحذف الصنف أو العميل نهائياً فقط عند عدم وجود معاملات أو مراجع محاسبية/مخزنية. يمنع النظام حذف السجلات المرتبطة بفواتير أو حركات أو أرصدة حتى لا تختفي من تقارير المخزون وكشوف الحسابات.
- أضيف إلغاء الفواتير المرحّلة بإنشاء قيود يومية وحركات مخزون عكسية، مع إبقاء المستند الأصلي وسجل التدقيق.
- يمنع إلغاء حركة مخزون تاريخية عند وجود حركات أحدث للصنف نفسه حتى لا تتشوّه تكلفة المخزون بأثر رجعي.
- لا تتوفر عمليات الحذف والإلغاء عند العمل دون اتصال؛ يجب تنفيذها مباشرة على قاعدة البيانات لضمان الذرية وسلامة الأرصدة.

## الهوية الرسمية للفواتير ومشاركة واتساب — الإصدار 2.2.3

- إضافة الترويسة الرسمية المرفقة من محلات الشيباني إلى فواتير المعاينة والطباعة A4 وصورة PNG.
- تضمين بيانات العنوان ورقمي واتساب `773837930` و`772533727` والهاتف الأرضي `02 383280` في صورة الفاتورة، وإظهارها في الإيصال الحراري بصورة مختصرة.
- زر مشاركة الفاتورة ينشئ صورة PNG محلياً داخل المتصفح ثم يستدعي واجهة المشاركة الأصلية `navigator.share` مع الملف؛ يختار المستخدم WhatsApp وجهة الاتصال ويؤكد الإرسال.
- إذا كان المتصفح لا يدعم مشاركة الملفات، ينزّل صورة PNG بدلاً من الادعاء بإرسالها تلقائياً. لا يستطيع المتصفح إرفاق الصورة برسالة واتساب دون اختيار المستخدم وتأكيده.
- أضيفت صورة الترويسة إلى ملفات Service Worker حتى تكون متاحة عند إعادة فتح التطبيق دون اتصال بعد تخزينها أول مرة.

## تحسين واجهة قائمة الأصناف للجوال

- أصبحت قائمة الأصناف تعرض بطاقات مدمجة على الشاشات التي يقل عرضها عن 760px، مع إبقاء جدول البيانات التفصيلي للشاشات الكبيرة.
- عُدلت الهوامش الجانبية لتستفيد القائمة من عرض الهاتف، وأصبحت أدوات البحث والإضافة والاستيراد وقالب الاستيراد وتسوية الجرد مرتبة في شبكة أزرار مناسبة للمس.
- تعرض بطاقة الصنف الاسم والوحدة والتصنيف والرمز والوحدات المسعرة والرصيد وحالة المخزون، وتوفر الإجراءات وفق صلاحية المستخدم.
- البحث يفلتر بطاقات الهاتف وصفوف الجدول بنفس الوقت.
- أزيل اختصار شاشة استعراض التصميمات من شريط الأدوات التشغيلي العام، مع الإبقاء على أداة الاختبار المتاحة في وضع المحاكاة.
- رُفع إصدار مخزن Service Worker لإبطال الواجهة القديمة وتحميل ملفات التصميم الجديدة.
- أضيفت فحوصات آلية ساكنة لقائمة الهاتف، وبحثها، وإجراءاتها، ونقاط التوقف المتجاوبة.
